# Glossary

**Last updated:** 2026-11-05
**Rule:** if a term is ambiguous in a conversation, link here and fix the entry.

---

## Domain

**DT (Drift Tube)** — CMS muon chamber technology: layers of drift cells.

**Cell** — the gas/drift volume and its centre. In CMS it is a box
(`width × length × thickness`); in general it can be a tube/cylinder or another
primitive. The cell is the sensitive volume in simulation. In
`DTGeometry_v3.xml`, the `<Wire>` element is the **cell entry** (number +
position); there is no separate wire object.

**Layer** — one plane of cells (4 layers per super layer in CMS). Cells repeat
along the layer's local x with a pitch and a stagger.

**Super layer (SL)** — a stack of layers sharing a cell orientation. CMS has
SL1 and SL3 with cells along the beam (y) and SL2 rotated by 90° about z.

**Station / chamber** — one DT chamber, made of super layers (3 in MB1–MB3,
2 in MB4).

**Wheel / sector / station number** — CMS addressing:
`wheel ∈ [-2, 2]`, `sector ∈ [1, 14]`, station type `∈ [1, 4]` (MB1–MB4).
Sectors 13/14 are the split MB4 sectors 4/10.

**Face orientation** — the sign that makes local station axes point
consistently toward/away from the interaction point; depends on wheel and, for
wheel 0, on sector. A CMS preset concern, not a core concept.

**MB4** — the fourth station type; it has no SL2 and uses SL3 for the
honeycomb reference.

**Honeycomb** — the aluminium layer between SL2 and SL1 (or SL3 for MB4);
generated by the simulator, not part of the DT cell model.

## Model

**Spec** — an immutable, JSON-able description of a geometry node
(`StationSpec`, `LayerSpec`, ...). No I/O, no behaviour beyond validation.

**Source** — an object that produces specs: `CMSXMLSource`, `JSONSource`,
Python builders.

**Builder** — the function that turns specs into runtime nodes and composes
`world_pose` top-down.

**Node** — an element of the runtime topology: detector, station, super layer,
layer or cell. A node may own a `Shape` or be a pure grouping frame.

**Grouping node** — a node with `shape=None` (e.g. an SL or layer in CMS). It
contributes a pose to its children but produces no volume.

**Shape** — a primitive solid in the node's local frame: `Box`, `Tube`,
extensible. Provides `aabb()`, `volume()`, `symmetry_axis()`.

**AABB** — axis-aligned bounding box, as full extents `(dx, dy, dz)`. Used for
placement, overlap and the legacy `bounds`; not the shape parameters.

**CellGrid** — the repetition of cells (pitch, count, stagger, first id).
Never call the grid a "wire layout".

**Material** — a name (`G4_AIR`, `GAS`, `G4_Al`, `G4_Fe`, ...) carried by a
node; the backend resolves it. The core does not build materials.

**Attachment / `SolidSpec`** — a passive solid attached to a station; the
honeycomb is the current case (box, aluminium).

**Structure / `StructureSpec`** — a detector-level solid with optional
subtractions; the yoke is the current case. The core stores the data; CSG is a
backend concern.

## Transforms

**Pose** — rigid transform from a child frame to its parent:
`p_parent = R·p_child + t`. One per node.

**World pose** — the composed pose from a node to the detector/world root,
computed top-down and cached.

**Frame** — a named coordinate system (station, SL2, layer, cell, CMS, a
virtual frame, ...).

**Frame id** — a unique path, e.g. `/CMS/W-2/S1/MB2/SL2/L1/C7`.

**Alias** — a short name resolved in an object's scope: `Cell`, `Layer`,
`SuperLayer`, `SL2`, `Station`, `CMS`, `World`.

**FrameGraph** — the shared graph of frame edges (one per node) with BFS/cached
path composition.

**FrameView** — the per-object view returned by `obj.transformer`; resolves
aliases and forwards `get_transformation`/`transform`.

**Virtual frame** — a frame that is not a geometry node, e.g. `StationNvPhi`,
`StationNvEta`, `SectorRef`, `SL13Center`; registered by the CMS preset.

**SL13Center** — the CMS reference frame at the midpoint of the SL1 and SL3
centres, used by the AM segment code.

**StationNvPhi / StationNvEta** — the "natural view" frames used by the
matplotlib patches for phi/eta views.

**Point vs vector** — `transform(..., type="point")` applies rotation +
translation; `type="vector"` applies rotation only.

## Event objects

**Annotation** — an event-level object anchored to a frame (station, SL, cell,
CMS) with an opaque attribute bag and an optional style. It is not a detector
solid and never enters the geometry spec/exporter.

**Segment** — a straight annotation: two endpoints or centre + direction +
length. The current `Segment`/`AMDTSegment` are constructors of this type.

**Track** — an ordered polyline (muon path) with optional per-point attributes
(time, energy loss, ...). Usually stored in `CMS`.

**Jet / Cone** — an annotation with an apex, an axis and a half-angle (plus
pT/energy). A visual cone, not a solid.

**Annotation collection** — `Segments`, `Tracks`, `Jets`: iteration, filtering,
`groupby`, `to_dataframe`; no geometry behaviour.

## Export / backends

**VolumeSink** — the backend-agnostic exporter interface:
`begin(root)`, `place(node, mother, pose_in_mother)`, `end()`. Implemented
with the first exporter (`TgSink`) in Phase 5.

**Backend** — an implementation of `VolumeSink`: a future pyg4ometry bridge, a
`.tg` writer, a GDML writer, or a test double (`RecordingSink`).

**Placement folding** — composing the poses of grouping nodes into the next
node that owns a solid, so a cell's placement is relative to its nearest volume
ancestor.

**`.tg`** — Geant4 ASCII text geometry, currently consumed by
`G4tgbVolumeMgr`.

**GDML** — Geometry Description Markup Language; Geant4 reads it with
`G4GDMLParser`. The intended output of a future pyg4ometry backend.

**pyg4ometry** — Python library for Geant4 geometry, materials, GDML, VTK and
overlap checks. Optional and deferred (ADR-008).

**`DTGEOMETRY`** — the current module-level XML singleton; to become a
deprecated shim over `CMSXMLSource`.

**`rawId`** — the CMS XML identifier of a node. Kept as metadata; never used as
a frame id.

## Process

**Oracle** — the XML `GlobalPosition` of every cell, used to validate computed
centres (`< 1e-3` cm).

**Node snapshot** — the representative-chamber check of node fields (id,
number, bounds, direction, local pose) against the XML; it replaced the
separate golden JSON (T-002 folded into T-003).

**`BUG-01` … `BUG-06`** — the tracked issues in `state.md` (SL2 transform,
cache mutation, attribute parsing, box-only bounds, frame-name divergence,
version drift).

**ADR** — Architecture Decision Record in `decisions.md`.

**Phase** — a shippable stage in `plan.md` Rev 4 (0 safety net, 1 specs +
source, 2 runtime model, 3 assemblies/extras, 4 optional events, 5 authoring/
`.tg`, 6 deferred backend).

**Ticket** — the unit of work (`T-0xx`), one file in `tickets/`, one branch and
one PR. Status: proposed/ready/doing/review/done/blocked/deferred.

**Epic** — a group of tickets (`E0` safety net, `E2` model, ...).

**Checkpoint** — a dated state in `PROGRESS.md` (`CP-003`), with evidence.

**Milestone** — a phase gate (`M0`…`M6`) defined in `TICKETS.md` §5.
