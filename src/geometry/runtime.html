Runtime model

Version 2.3 rebuilt the geometry core around four small layers. The classes documented in Station, SuperLayer, Layer and DriftCell are still there and keep their API; internally they are thin views over the pipeline below.

DTGeometry_v3.xml
      |  CMSXMLSource              one indexed parse per process
      v
StationSpec / DetectorSpec         frozen dataclasses: Pose, Shape, CellGrid
      |  build_station             one node tree per chamber (cached)
      v
Node tree                          parent-relative Pose, cached world_pose
      |  FrameGraph / FrameView    scoped aliases: Station, SL2, L1, Cell, CMS
      v
legacy views                       Station, SuperLayer, Layer, DriftCell

Nothing below the XML layer imports xml.etree: the specs are plain dataclasses, the builder is numpy only, and the graph composes 4x4 matrices. A cell is the XML <Wire> entry; there is no separate wire object.

Poses and units

Every node stores one pose relative to its parent (p_parent = R . p_child + t), in cm, and the builder composes and caches its world pose once, top-down. Rotations are intrinsic and orthonormal; the spec validator rejects non-finite values, non-orthonormal rotations and shapes that are not positive.

Assemblies and custom stations

A detector is the root of the same node tree: build_detector hangs every station of a DetectorSpec under it at its own pose, so one graph holds the whole assembly. A chamber that is not in the CMS XML gets the legacy views with Station.from_spec: the values those classes read (local centres, bounds, direction, raw ids) are derived from the node tree, so the same plotting patches draw it. A super layer is chosen for the phi or the eta view by its orientation, not by its number.

"""A station that is not in the CMS XML: one and five super layers (T-030).

The geometry is described with specs only. Station.from_spec gives the same
legacy views, and therefore the same plotting patches, as a CMS chamber.
"""

import matplotlib.pyplot as plt

from mpldts.geometry import Station, build_detector
from mpldts.geometry.specs import (
    Box,
    CellGrid,
    DetectorSpec,
    LayerSpec,
    Pose,
    StationSpec,
    SuperLayerSpec,
)
from mpldts.patches import DTStationPatch

DPI = 100


def layers():
    """Four layers of eight cells (4 cm pitch, 8 cm long, 1.3 cm thick)."""
    return [
        LayerSpec(
            number=number,
            pose=Pose.translated(0.0, 0.0, (number - 2.5) * 2.5),
            cells=CellGrid(pitch=4.0, count=8, shape=Box(4.0, 8.0, 1.3)),
        )
        for number in range(1, 5)
    ]


def station_spec(name, number_of_super_layers, pose):
    """A super layer every 9.5 cm along z, centred on the station frame."""
    centre = (number_of_super_layers - 1) / 2.0
    super_layers = [
        SuperLayerSpec(
            number=number,
            pose=Pose.translated(0.0, 0.0, (number - 1 - centre) * 9.5),
            layers=layers(),
            shape=Box(32.0, 8.0, 8.8),
        )
        for number in range(1, number_of_super_layers + 1)
    ]
    return StationSpec(
        name=name,
        pose=pose,
        super_layers=super_layers,
        shape=Box(32.0, 8.0, (number_of_super_layers - 1) * 9.5 + 8.8),
    )


# One detector, two stations: the assembly is a single node tree
detector = DetectorSpec(
    name="two custom chambers",
    pose=Pose.identity(),
    stations=[
        station_spec("one_sl", 1, Pose.rotated_z(30.0, (100.0, 0.0, 0.0))),
        station_spec("five_sl", 5, Pose.rotated_z(-45.0, (-100.0, 0.0, 0.0))),
    ],
)
detector_node = build_detector(detector)
print([station.name for station in detector_node.children])

Authoring: short constructors and JSON

Four constructors fill the defaults that a hand-written spec should not repeat (identity pose, no envelope, air in the chamber, vacuum in the world). They do not validate eagerly: validate stays the single gate, so a spec built with them fails where a hand-built one fails.

The assembly: the stations of the detector and the world frame.

A spec saves to a JSON document and loads back into the same spec (mpldts.station/2 for a chamber, mpldts.detector/2 for an assembly). The document holds poses, shapes and names and nothing derived: cell centres and world poses are rebuilt from it, so a file cannot disagree with the model. It is strict on the way in, because a typo in a detector description is a detector that is silently wrong.

  "name": "TB-1",
  "pose": {"rotation": [[1, 0, 0], [0, 1, 0], [0, 0, 1]], "translation": [0, 0, 0]},
  "shape": {"kind": "box", "dx": 160.0, "dy": 100.0, "dz": 37.3},
  "material": "G4_AIR",
  "super_layers": [{
    "number": 1,

    "layers": [{
      "number": 1,
      "pose": {"rotation": [[1, 0, 0], [0, 1, 0], [0, 0, 1]], "translation": [0, 0, -3.0]},
      "cells": {
        "pitch": 20.0, "count": 8, "first_id": 1, "offset": 0.0,

    }]

}

The rotation is a 3x3 matrix in rows and the translation is a triple, both in the parent frame; a box carries its full dimensions and a tube its radius, length and axis. Unknown keys are errors, and so are a missing field, a wrong type, an unknown shape kind, a rotation that is not orthonormal and a grid that does not fit its layer.

Exporting to Geant4 (.tg)

An exporter never walks the tree itself: it implements a sink and receives the placements. Only nodes with a solid become volumes; the grouping frames (super layer, layer) are folded into the pose of the placement, and a station’s attachments (the honeycomb) are visited after the cells.

class mpldts.export.base.VolumePlacement(node: Node, mother: Node | None, pose_in_mother: Pose)[source]

One solid to place: its node, its mother (None = the world) and the pose.

class mpldts.export.base.VolumeSink(*args, **kwargs)[source]

Minimal contract every exporter backend implements.

mpldts.export.base.iter_volume_placements(root: Node) → Iterable[VolumePlacement][source]

Pre-order walk that folds nodes without a solid into the next placement.

A node with a shape becomes a volume of its mother; a grouping node only contributes its pose, so its children hang off the same mother. Attachments come after the regular children, so the honeycomb is placed after the cells.

mpldts.export.base.export_volumes(root: Node, sink: VolumeSink) → None[source]

Drive any backend from the placement walk.

class mpldts.export.base.RecordingSink(placements: List[VolumePlacement] = <factory>, root: Node | None = None)[source]

Sink that only records the placements; the test double for any backend.

mpldts.export.tg.TgSink writes that walk as a Geant4 ASCII geometry file, the .tg format DTG4Simulator reads with G4tgbVolumeMgr. It writes the solids, the volumes and the placements only: the world volume and the identity rotation R0 belong to the document that includes the file. Volume and rotation names are qualified by the exported root, so several station files can be included in one document without redefining anything.

class mpldts.export.tg.TgSink(target, world: str = 'world')[source]

exception mpldts.export.tg.TgFormatError[source]

The example below is the whole path: build the spec with the short constructors, write the JSON document, read it back, build the node tree from the document, plot the chamber with the legacy patches and export the volumes.

"""Author a station, save it as JSON and export it as a .tg file (Phase 5).

The whole authoring path: build the spec with the short constructors, write the
JSON document, read the document back, build the node tree from it, plot the
chamber, and export the volumes for Geant4.

The .tg file is the format DTG4Simulator reads with G4tgbVolumeMgr; it holds the
placements only, so it is included from a document that defines the world volume
and the identity rotation R0.
"""

import matplotlib.pyplot as plt

from mpldts.export import TgSink, export_volumes, iter_volume_placements
from mpldts.geometry import Station, build_station
from mpldts.geometry.constructors import make_layer, make_station, make_superlayer
from mpldts.geometry.serialize import from_json, to_json
from mpldts.geometry.specs import Box, CellGrid, Pose
from mpldts.patches import DTStationPatch

DPI = 100
PITCH = 20.0


def layers():
    """Four layers of eight long cells, 2 cm apart along z."""
    return [
        make_layer(
            number,
            CellGrid(pitch=PITCH, count=8, shape=Box(PITCH, 100.0, 1.3), material="GasMixture"),
            pose=Pose.translated(0.0, 0.0, (number - 2.5) * 2.0),
        )
        for number in range(1, 5)
    ]


def super_layers():
    """Three super layers every 9.5 cm, the middle one turned by 90 degrees."""
    return [
        make_superlayer(
            number,
            layers(),
            pose=Pose.rotated_z(90.0 if number == 2 else 0.0, (0.0, 0.0, (number - 2) * 9.5)),
        )
        for number in range(1, 4)
    ]


station = make_station(
    "testbeam chamber",
    super_layers(),
    shape=Box(8 * PITCH, 100.0, 3 * 9.5 + 8.8),
)

# 1. The document: poses, shapes and names, nothing derived. Read it back and
# the station is the same one, so the file can be edited by hand.
document = to_json(station)
with open("./testbeam_station.json", "w") as handle:
    handle.write(document)
restored = from_json(document)
print("station:", restored.name, " (%d bytes of JSON)" % len(document))
print("super layers:", [sl.number for sl in restored.super_layers])

# 2. The node tree: the same builder the CMS chambers use. Only the station
# and the cells are solids; super layers and layers are grouping frames.
node = build_station(restored)
print("volumes:", len(list(iter_volume_placements(node))))

# 3. The geometry for Geant4: one solid per super layer, one placement per cell.
export_volumes(node, TgSink("./testbeam_station.tg"))
print("wrote ./testbeam_station.tg")

# 4. The plots: the legacy patches work on a station that is not in the XML.
view = Station.from_spec(restored)
width, height, length = view.bounds
x, y, z = view.local_center
figure, axes = plt.subplots(1, 2, figsize=(13, 5), dpi=DPI)
for axis, faceview in zip(axes, ("phi", "eta")):
    DTStationPatch(view, axis, faceview=faceview, local=True)
    if faceview == "phi":
        axis.set_xlim(x - width / 2 - 5.0, x + width / 2 + 5.0)
    else:
        axis.set_xlim(y - length / 2 - 5.0, y + length / 2 + 5.0)
    axis.set_ylim(z - height / 2 - 5.0, z + height / 2 + 5.0)
    axis.set_title("%s view" % faceview)
    axis.set_xlabel("x [cm]")
    axis.set_ylabel("z [cm]")
figure.suptitle("Authored station: JSON in, plot and .tg out")
plt.tight_layout()
plt.show()
figure.savefig("./testbeam_station.svg", dpi=DPI)

Immutability and per-event data

A chamber is built once and every Station is a view over that build, so the same object is shared by every caller. Per-event data therefore never goes on the shared geometry: use Station.overlay, which clones the view, keeps the node tree and the graph, and applies the drift-cell attributes to the clone.

from mpldts.geometry import STATION_CACHE

station = STATION_CACHE.get(-2, 1, 2)              # shared geometry
event = STATION_CACHE.get(-2, 1, 2, dt_info=[{"sl": 1, "l": 1, "w": 1, "t": 12.5}])
station.super_layer(1).layer(1).cell(1).t          # unchanged
event.super_layer(1).layer(1).cell(1).t            # 12.5

Cost on a warm process: importing mpldts.geometry does not touch the XML, the first build of a chamber is tens of milliseconds, and later stations are a few milliseconds each.

The downstream contract

DTPatternRecognition (dtpr) plots one event on top of these classes, so the names it imports are a contract: renaming any of them is a breaking change until 3.0 (ADR-025). test/downstream imports exactly this surface, with no ROOT and no Qt:

  • geometry: StationsCache (and STATION_CACHE), Station, AMDTSegments;

  • patches: DTStationPatch, MultiDTSegmentsPatch, DTRelatedPatch;

  • on the station: name/wheel/sector/number, super_layer(sl).layer(l).cell(w), Cell.local_center and global_center, Layer._first_cell_id/_last_cell_id and layer.cell(id);

  • on a patch: .station and ._collections (the visualizer iterates the collections to toggle its artists).

The per-event data dtpr sends is one row per hit, keyed by the cell:

rows = [{"sl": 1, "l": 1, "w": 2, "time": 400.0}, ...]
event = STATION_CACHE.get(0, 1, 1, dt_info=rows)

sl, l and w are required; every other column becomes an attribute of that cell on the returned overlay (time, BX, …), which is what DTStationPatch(vmap=...) colours by. A dict, a list[dict] and a pandas.DataFrame are all accepted, and the station in the cache is never mutated.

Migrating from 2.2

Nothing a user of 2.2 had to change, and nothing is deprecated yet (ADR-018: the legacy API stays until 3.0). What arrived, in order:

  • 2.3: the geometry is built once per process from DTGeometry_v3.xml into specs, a node tree and a frame graph. The constructors, the data attributes (local_center, global_center, direction, bounds, rawId) and the plotting patches behave as before.

  • 2.4: a chamber that is not in the XML: StationSpec/DetectorSpec, build_detector, Station.from_spec, the honeycomb as a station attachment, the yoke as detector structure data.

  • 2.5: authoring and export: the short constructors, the JSON documents and .tg output through TgSink.

  • 2.5.1: FrameView.available_frames lists the legacy names again (Station, CMS, SL{n}, the plotting virtual frames) next to the frame ids, so a reference frame given by name keeps resolving; the names are API until 3.0 (ADR-025).

Behaviour that did change, deliberately:

  • the SL2 transform is correct (BUG-01): super layer 2 cells used to be off by √2 . |SL_local_x|;

  • a phi/eta view picks its super layer by orientation, not by number == 2, so a custom chamber with a turned layer draws it where it is;

  • DTGEOMETRY parses the XML on first use, never at import;

  • per-event data goes through Station.overlay (or the cache with dt_info), which never mutates the shared chamber;

  • a cell that is exported needs a material: CellGrid.material carries it, and a physical node without one is an error rather than G4_AIR.
